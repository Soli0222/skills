# ネイティブのサブエージェント

実行環境が公開するツールの説明を読み、起動、連絡、完了通知、継続、停止の機能を確認する。
別の製品やセッションで使えたツール名・引数を仮定しない。

## 起動前

- 子が共有する会話、ファイルシステム、cwd、権限を確認する。
- 自動worktree隔離があるなら、作成先と回収・削除の責任を確認する。
- 必要な文脈だけを渡す。会話を継承する場合も、目的と担当境界は明示する。
- モデル指定はユーザーの希望と利用環境の規則に従う。
- 子の作業中に親が進める独立した仕事を決める。親の作業がなければ委譲の利益を再評価する。

## 指示の例

```text
目的: CSVエクスポートの文字化けを修正する。
担当: src/export/ と対応するテスト。UIと依存定義には触れない。
環境: 親と作業ツリーを共有する。Git操作は親が行う。別担当がsrc/ui/を編集中。
根拠: 適用される規約と、指定した再現手順を読んでから着手する。
完了: 再現ケースが成功し、既存のエクスポート挙動を維持する。
検証: 担当テストを実行する。全体の統合チェックは親が行う。
報告: 変更ファイル、変更点、実行コマンドと結果、残る懸念を返す。
担当外の変更が必要なら編集前に連絡する。
```

## 継続と回収

返されたagent IDを仕事と対応づける。
完了通知や待機機能を使い、短い間隔での状態照会を繰り返さない。
途中の質問には、他の担当にも影響する決定を共有して答える。

修正は同じagent IDへ具体的に返す。
停止要求を出しただけでファイルが確定したとみなさず、実行終了を確認してから引き取る。
共有作業ツリーなら差分を直接レビューし、隔離されていれば回収先とcommitまたはpatchを確認する。
報告メッセージは受け渡しに十分であり、同じ内容の報告書ファイルを追加で要求しない。
