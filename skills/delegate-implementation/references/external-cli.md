# 外部CLIへの委譲

ネイティブ委譲で要件を満たせない場合、またはユーザーが外部CLIを指定した場合に使う。
実装者固有の参照と、インストール済みCLIのhelpを確認して起動方法を組み立てる。
helpで分からない仕様は、そのバージョンに対応する公式資料で確認する。
認証や接続確認のために新しい実装セッションを不用意に起動しない。

## 起動契約

次を起動前に決める。

- cwdと編集可能範囲。worktreeを使うかは本文の基準で別途判断する。
- 非対話実行で使う権限と、承認待ち・拒否時の挙動。
- 入力の渡し方、出力と終了状態の取得方法、session IDの取得・再開方法。
- 長時間実行の追跡方法と停止方法。

通常の編集・検証に必要な権限を選ぶ。
権限不足なら、依存準備やコミットを親へ移す、書込先を調整するなど、必要な操作を切り分ける。
無人実行の都合だけで全権限モードへ切り替えない。
権限を広げる必要がある場合は、現在の許可範囲と環境の承認手続きに従う。
worktreeや事後監査で権限拡大を正当化しない。

長い指示や再開に必要な記録はタスク専用の一時ディレクトリへ置く。
CLIの最終出力に必要な報告が揃えば、別の報告書は作らせない。
ログと出力の保存先が実際に書き込める場所であることを確認する。

## 実行と再開

環境のプロセス管理機能を使って起動し、仕事とprocess/session IDを対応づける。
親のツール呼び出しが終わってもプロセスが継続するか、出力を後から取得できるか確認する。
並列実行中は「最後のセッション」を再開せず、IDを明示する。
起動と再開で使える引数や引き継がれる権限が異なる可能性があるため、それぞれ確認する。

再開できない場合は旧プロセスの終了を確認し、差分と残作業を新セッションへ渡す。
終了コード、結果出力、実際の差分、検証結果を照合して完了を判断する。
出力ファイルが存在することやCLIの正常終了だけで、実装完了とはしない。
